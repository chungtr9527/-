# Android notes (Capacitor 8, Android first)

What lives in `android/`, what was changed by hand after `npx cap add android`, how to build locally and in CI, how to
sideload the debug APK, and what could **not** be verified inside the development container.

## 1. What `android/` is

`android/` is the project generated by `npx cap add android` (Capacitor CLI 8.6.0, template AGP 8.13 / Gradle 8.14.3 /
compileSdk = targetSdk 36 / minSdk 24 / Java 21) and it is **committed**. Generated-on-every-sync files are git-ignored
by `android/.gitignore` and must never be edited:

| Path | Who writes it |
|---|---|
| `android/app/src/main/assets/public/` | `npx cap sync android` (copy of `www/`) |
| `android/app/src/main/assets/capacitor.config.json`, `capacitor.plugins.json` | `cap sync` |
| `android/app/src/main/res/xml/config.xml`, `android/capacitor-cordova-android-plugins/` | `cap sync` |
| `android/app/capacitor.build.gradle`, `android/capacitor.settings.gradle` | `cap sync` (committed, but regenerated each time; do not edit) |

`npx cap sync android` is idempotent and does **not** need the Android SDK; run it after every change to `www/` or to the
plugin set in `package.json`. The six plugins it wires up: `@capacitor/app`, `filesystem`, `haptics`, `preferences`,
`share`, `@capacitor-community/admob` 8.3.0.

## 3. Icon and splash pipeline (no ImageMagick, no design tool)

1. `www/tools/icon.html` (noindex) holds the icon SVG verbatim (plan §3) and renders it into canvases;
   `window.exportIcon(kind, size?)` resolves to a PNG data URL for `icon-only`, `icon-foreground` (transparent, tilted
   board scaled ×0.78 around the centre so adaptive masks never clip it), `icon-background` (solid `#0F1233`), `splash`
   and `splash-dark` (2732×2732, `#0F1233`, full icon at 20 % of the width, centred); `size` renders any kind as a
   square of that edge. Open it in a browser for previews and manual downloads.
2. `node scripts/export-icons.js` drives that page with the project's Playwright Chromium and writes `resources/*.png`,
   verifying each file's IHDR (1024×1024 ×3, 2732×2732 ×2). `test/unit/android-project.test.js` re-checks the sizes.
3. `npx @capacitor/assets generate --android --assetPath resources --iconBackgroundColor "#0F1233" --iconBackgroundColorDark "#0F1233" --splashBackgroundColor "#0F1233" --splashBackgroundColorDark "#0F1233"`
   writes `mipmap-{ldpi..xxxhdpi}/ic_launcher{,_round,_foreground,_background}.png`, `drawable*/splash.png`
   (`-night` variants from `splash-dark.png`), rewrites `mipmap-anydpi-v26/ic_launcher*.xml` **with** a 16.7 % inset
   and re-serialises `AndroidManifest.xml` (diff it afterwards; the §2 edits must survive).
4. `node scripts/export-icons.js --android` fixes the tool's two adaptive-icon defects: it re-renders
   `ic_launcher_foreground.png` / `ic_launcher_background.png` at the real 108 dp sizes for every density and rewrites
   both `mipmap-anydpi-v26/*.xml` without the inset. The unit test fails if either fix is missing.
   The header comment of those XML files deliberately spells the flag as `export-icons.js  - android` (one dash):
   XML 1.0 forbids the sequence `--` inside a comment and aapt2 refuses to compile a resource that contains one, so
   never write `--android` (or any other `--`) inside an XML comment under `android/`.

Change the icon → edit the SVG string in `icon.html` → run 2, 3 and 4 → commit `resources/` and `android/`.

## 4. Building locally

Requirements: Android Studio **Otter (2025.2) or newer** (bundled JDK 21 and SDK 36 / build-tools 36), or a plain JDK 21 +
Android SDK with `ANDROID_HOME` set. Node 22.

```bash
cd sandslide
npm ci
npm run flags:dev            # env 'test' (Google test ad units), debug hooks on; the debug strings already force the sample app id
npx cap sync android         # copies www/ and (re)generates the plugin gradle files
npx cap open android         # Android Studio: Run ▶ on a device or emulator
# or without the IDE:
cd android && ./gradlew assembleDebug --no-daemon        # app/build/outputs/apk/debug/app-debug.apk (signed with app/debug.keystore)
```

Release build (what the `sandslide-android-release` workflow does on a `vX.Y.Z` tag):

```bash
npm run flags:release        # env 'prod', removes ads-ids.test.js — needs the real ids pasted first
npx cap sync android
export KEYSTORE_PATH=/abs/path/upload.jks KEYSTORE_PASSWORD=... KEY_ALIAS=upload KEY_PASSWORD=...
cd android && ./gradlew bundleRelease assembleRelease -PappVersionName=0.1.0 -PappVersionCode=100
npm run flags:dev            # switch the working tree back
```

Without `KEYSTORE_PATH` the release outputs are unsigned (`app-release-unsigned.apk`); Play needs the signed AAB.

## 5. Building in CI (`.github/workflows/sandslide-android-debug.yml`)

* Triggers: every push that touches `sandslide/**` or the workflow file, on **any** branch, plus `workflow_dispatch`
  (the manual button only appears once the workflow file is on `main`; until then push to a `claude/*` branch).
* Runner `ubuntu-24.04` (Android SDK 36 + build-tools 36 pre-installed, so there is no SDK install step), Temurin 21,
  Node 22 with the npm cache keyed on `sandslide/package-lock.json`, Gradle cache via `setup-java`.
* Steps: `npm ci` → `npm run flags:dev && npx cap sync android` → `./gradlew assembleDebug --no-daemon --stacktrace`
  → artifact **`sandslide-debug-<commit sha>`** (14-day retention) containing `app-debug.apk`.
* The first two runs on GitHub were green, which is the real verification of the native dependency set (AdMob plugin
  8.3.0: Kotlin 2.2.20, `play-services-ads 25.4.+`, `user-messaging-platform 4.0.0`,
  `io.github.webview-native-ui:engine:1.0.0`). If a later run fails on dependency resolution, pin
  `@capacitor-community/admob` to 8.2.0 (plan §10.3) and re-run.

## 6. Sideloading the debug APK

1. GitHub → the repository → **Actions** → the `sandslide-android-debug` run for your commit → **Artifacts** →
   `sandslide-debug-<sha>` (you must be signed in to GitHub to download; it is a zip).
2. Unzip; send `app-debug.apk` to the phone (USB, Google Drive, Nearby Share, or e-mail it to yourself).
3. On the phone open the file. Allow **Install unknown apps** (設定 → 應用程式 → 特殊應用程式存取權 → 安裝不明應用程式)
   for the app you opened it from (Files / Chrome / Drive). Play Protect may ask to scan it — accept.
4. Later builds install **over** the previous one (same package id, same committed debug key) and keep the saved game,
   settings and stats. If a build signed with a different key is already installed (e.g. one from Android Studio with
   your machine's own `~/.android/debug.keystore`), uninstall it first.
5. With a cable: `adb install -r app-debug.apk`.

Debug builds show **Google test ads only** (sample app id + test unit ids via `flags:dev`), so they can be clicked freely.

## 7. Test devices (AdMob) and testers (Play)

The closed-test and production builds use `env: 'prod'`, i.e. live ad units. Any phone that will run those builds must be
registered as an AdMob test device, otherwise your own and your testers' taps count as invalid traffic:

1. On the phone: **Settings → Google → Ads** (設定 → Google → 廣告) — on Android 13+ it may be under
   **Settings → Privacy → Ads** (設定 → 隱私權 → 廣告) — and copy the *advertising ID* (`xxxxxxxx-xxxx-…`). No logcat needed.
2. AdMob console → **Settings → Test devices → Add test device** → platform Android, "Add your device manually", paste the
   ID, name it. Up to 100 devices; it takes effect in a few minutes and expires after 30 days of inactivity.
3. Optional: paste the same IDs into `testingDevices` in `TB.Config.ADS` for the `initialize()` call (test env only).
4. Google Play testers: Play Console → Testing → Internal / Closed testing → **Testers** → a Google Group or a list of
   e-mail addresses → share the opt-in link; a personal developer account created after 2023-11-13 needs 12 testers
   opted in for 14 continuous days before production access can be requested (plan §1.1).
5. Tell testers not to click ads deliberately (`docs/tester-guide.md`).

## 8. Not verifiable in the development container

* **Gradle never ran here**: there is no Android SDK and `dl.google.com` is blocked, so `app/build.gradle`, the
  `-P` version properties, the signing blocks and the AdMob plugin's native dependencies are validated only by the
  `sandslide-android-debug` workflow (its first two runs on GitHub were green). `npx cap add android` / `npx cap sync android` and
  `@capacitor/assets` were run and are consistent; all edited XML files are well-formed (parsed with `xml-js`).
* Portrait lock: with targetSdk 36, Android 16 ignores `screenOrientation` on large screens (tablets, unfolded
  foldables); the layout already letterboxes landscape, so this is cosmetic.
* 16 KB page-size compliance: the app is pure Java/Kotlin + WebView, no `.so` expected; the release workflow fails if the
  AAB contains any.
* Themed (monochrome) launcher icon for Android 13+ is not provided; the launcher falls back to the coloured icon.
* Real-device matrix (gesture vs 3-button navigation × WebView < 140 / ≥ 140): banner inset, back button, pause/resume,
  black screen after a rewarded ad — plan §9.
